# EVTX Audit v11 — проверка выгрузок журналов Windows на объектах КИИ / АСУ ТП

Скрипт `Audit-Evtx-11.3.ps1` (в имени файла — версия) прогоняет выгруженные журналы `.evtx` через набор правил
**Sigma** — как программа Chainsaw, но на PowerShell и встроенном .NET (Windows
PowerShell 5.1, без установки ПО). Каждое событие, попавшее под правило, становится
строкой листа **«Нарушения»** с уровнем, временем, компьютером, пользователем и
деталями; строки подсвечены по уровню. Правила написаны под АСУ ТП: упор на
**действия персонала, запрещенные регламентом** (смена времени, учетные записи,
съемные носители и телефоны, установка ПО и служб, отключение защиты, очистка журналов,
перезагрузки, Wi-Fi и модемы). Признаки атак — отдельная группа правил.
Результат — книга Excel (или CSV, если Excel не установлен).
Журналы, учетные записи, политику аудита и политику исполнения скрипт не изменяет.

## Быстрый старт

Откройте новое окно Windows PowerShell. Скрипт не меняет политику исполнения.
Если SelfTest завершится ошибкой, основной анализ не начнётся.

```powershell
cd "C:\Users\VATukkaev\Desktop\audit script";
$ErrorActionPreference = 'Stop';
$EvtxRunner = [scriptblock]::Create((Get-Content -LiteralPath '.\Audit-Evtx-11.3.ps1' -Raw -Encoding UTF8 -ErrorAction Stop));
try {
    & $EvtxRunner -SelfTest;
    $Logs = Read-Host 'Вставьте общую папку с логами';
    $Out = Read-Host 'Вставьте папку для новых результатов';
    $RunParams = @{ InputPath = $Logs.Trim().Trim('"'); OutputPath = $Out.Trim().Trim('"') };
    # $RunParams.StartTime = '2026-09-01';                          # только период: самый сильный способ ускорить
    # $RunParams.SigmaRulesPath = 'D:\sigma\rules\windows\builtin';  # дополнительные правила Sigma
    # $RunParams.AttackTriage = $true;                              # дополнительно листы поиска атак
    & $EvtxRunner @RunParams;
} catch {
    Write-Host 'Остановлено из-за ошибки:' -ForegroundColor Red;
    $_.Exception.Message;
    $_.ScriptStackTrace;
}
```

Команды заканчиваются `;` и не содержат пустых строк: при вставке в консоль PowerShell
переносы строк иногда теряются, и без `;` соседние строки склеиваются в одну команду.

Успешный SelfTest заканчивается строкой `ALL SELFTESTS PASSED — version 11.3.0`.
Удобнее всего класть выгрузку каждого компьютера в свою подпапку (можно целиком
`C:\Windows\System32\winevt\Logs`): цепочки событий строятся внутри одной папки и
одного компьютера.

В начале запуска печатается **«Режим обработки»**: `C# (скомпилированное ядро)` —
нормальный быстрый режим; `PowerShell (совместимый)` — C#-код не удалось
скомпилировать (например, csc.exe запрещён AppLocker/EDR): анализ выполняется
полностью, но медленнее и **без правил Sigma — лист «Нарушения» не заполняется**.
Причина — на листах «Ошибки» и «Запуск».

## Листы книги

| Лист | Что в нем |
|---|---|
| **Сводка** | компьютер × число нарушений по уровням (критические и высокие / средние / низкие) и по каждой группе (время, учетные записи, права и группы, носители, ПО…; 0 — проверено, не найдено), затронутые учетные записи (созданные, удаленные, измененные, добавленные в группы), найденные цепочки, основные нарушения, входы, RDP, носители, период событий, глубина журнала Security, замечания о неполной выгрузке и о выключенном аудите управления учетными записями |
| **Нарушения** | главный лист: одно событие — одна строка. Уровень, время (местное и UTC), компьютер, группа, нарушение (все сработавшие правила), пользователь (кто сделал), учетная запись (объект — кого создали, изменили, добавили в группу), детали (поля события, важные для правила), повторы, Event ID, журнал, файл, Record ID. Высокий и критический — красным, средний — желтым |
| **Цепочки** | связанные события (корреляции Sigma): «носитель → установка ПО», «установка → очистка журнала», «временная учетная запись», «новая УЗ сразу в администраторы», «вход под только что созданной УЗ», многократные неудачные входы и др. — с ходом событий и ссылками на них |
| **Правила** | все правила и цепочки, по которым проверялась выгрузка, со счетчиком срабатываний; 0 — проверено, нарушений не найдено. Описание и возможные законные причины |
| **Входы** | кто, куда и откуда входил: успешные и неудачные входы, типы входа, коды отказа с расшифровкой |
| **RDP_сеансы** | удаленные сеансы с длительностью |
| **Съемные_носители** | один носитель — одна строка: серийный номер, модель, на каких компьютерах подключался, вероятные пользователи |
| **Находки** | все отобранные события (только нужные столбцы) |
| **Качество_выгрузки**, **Файлы**, **Ошибки**, **Запуск** | каких журналов не хватает, обработка каждого файла, ошибки, параметры запуска |

С ключом `-AttackTriage` добавляются листы эвристического поиска атак
**Инциденты**, **Приоритетные** и **Подбор_пароля** (как в v9–v10).

## Как работать с отчетом

1. **«Сводка»** — какие компьютеры смотреть в первую очередь и чего не хватает в выгрузке.
2. **«Нарушения»** — включите фильтр по столбцу «Компьютер» или «Уровень» и пройдите
   строки по времени. «Повторов» > 1 — одно и то же нарушение повторялось в течение минуты
   (несколько записей одного подключения, серия отказов) и показано одной строкой.
   «Пользователь» — кто совершил действие; для подключения устройств (их пишет SYSTEM)
   указан **вероятный** пользователь — чей интерактивный или RDP-вход был активен в этот
   момент. SID заменяется именем, если оно встречается в журнале Security.
3. **«Цепочки»** — связанные нарушения, которые по отдельности могли выглядеть безобидно.
4. **«Правила»** — что проверено и сколько найдено; столбец «Возможные причины»
   подсказывает законные объяснения (заявка, плановое обслуживание).
5. Исходное событие: по «Номер находки» на листе «Находки» или по файлу и Record ID в EVTX.

## Правила Sigma (встроенный пакет)

110 правил и 20 цепочек; группы на листах отчета:

| Группа | Что ловится |
|---|---|
| Изменение времени | смена системного времени пользователем (4616, без службы синхронизации) |
| Учетные записи | создание, удаление, включение, отключение, сброс пароля, переименование, изменение параметров (флаги UAC расшифровываются: «+пароль бессрочный» и т. п.), разблокировка; скрытая УЗ `имя$`; включение Гостя; УЗ компьютеров; ослабление защиты УЗ (без предаутентификации Kerberos, делегирование, DES, обратимое шифрование пароля); пароль не требуется или бессрочный; неудачная смена или сброс пароля; просмотр УЗ и групп командами `net`, `whoami`, PowerShell; пароль DSRM |
| Права и группы | добавление в администраторы и операторы, в группы RDP/WinRM, прочие изменения членства, назначение прав и прав входа |
| Входы в систему | вход встроенным Администратором, runas, вход вне разрешенного времени или с неразрешенного компьютера, пароль в открытом виде, блокировка УЗ |
| Удаленный доступ | RDP-вход, RDP с внешнего адреса, установка TeamViewer, AnyDesk, RMS, Radmin, VNC, LiteManager и др. (служба и MSI) |
| Съемные носители | USB-накопители и карты (Security 6416, Kernel-PnP 400/410, Partition 1006), телефоны и другие MTP-устройства, запрет установки устройства политикой (6423) |
| Сеть и периферия | USB-модемы и сетевые адаптеры, подключение к Wi-Fi, печать документов |
| Установка ПО и служб | установка, удаление и изменение программ (MsiInstaller), новые службы и драйверы, изменение типа запуска служб, обновления Windows (без сигнатур антивируса), задания планировщика |
| Запуск программ | блокировка и аудит AppLocker, Code Integrity, запуск Windows PowerShell |
| Средства защиты | Defender и Kaspersky (см. ниже): обнаружение ВПО, неудачное обезвреживание, выключение защиты, исключения, вмешательство в работу антивируса; удаление антивируса, отключение его службы, «антивирус выключен» в Центре безопасности Windows; отключение служб защиты и журнала, изменение брандмауэра |
| Журналы и аудит | очистка журналов, изменение политики аудита пользователем, потеря событий |
| Перезагрузки и сбои | перезагрузка или выключение пользователем (1074), аварийное выключение (41, 6008), BSOD |
| Признаки атаки | PsExec/Impacket, SID History, Pass-the-Hash, перебор учетных записей, распределенный подбор пароля, Kerberoasting |

Цепочки: носитель → установка программы или службы (30 мин), носитель → обнаружение
ВПО, выключение защиты → подключение носителя (1 ч), 5 и более обнаружений угроз за час, изменение времени + очистка журнала, установка → очистка журнала, ослабление защиты →
установка, временная (создана и удалена) и временно включенная УЗ, массовое создание УЗ, новая УЗ
сразу добавлена в администраторы, вход под только что созданной УЗ, временное добавление в
администраторы (добавлен и удален за сутки), массовая блокировка УЗ (3 и более за 10 мин),
многократные неудачные входы одной УЗ, RDP одной УЗ с разных адресов и атаки выше.


### Антивирус Касперского

Kaspersky Endpoint Security (KES), Kaspersky Security для Windows Server и KICS for Nodes пишут
события в журнал **Kaspersky Event Log** (или «Kaspersky Security») и, если включено в политике,
в **Application**. Для анализа выгрузите и эти журналы:
`wevtutil epl "Kaspersky Event Log" Kaspersky.evtx` (имя журнала — в «Просмотре событий»,
«Журналы приложений и служб»). Файлы с «kaspersky» в имени читаются целиком, без ограничения
Event ID.

Коды событий у KES разных версий и у других продуктов Касперского не совпадают, поэтому
правила смотрят на **текст события** — строки «Тип события: …», «Объект\Путь: …»,
«Результат\Название: …» на русском или английском. Если KES 11–12 пишет в Application только
параметры (SHA256, имя объекта), используются коды событий Windows из документации KES
(302, 303, 306, 307, 312, 362, 363, 651, 802, 2200, 206–214). В «Деталях» — угроза, объект,
результат, компонент, устройство или программа; пользователь берется из события, а если там
SYSTEM — показывается вероятный пользователь (кто был в системе).

| Уровень | Нарушение (лист «Нарушения») |
|---|---|
| Критический | угроза не устранена: объект не вылечен, не удален, активная угроза; цепочка «выключение защиты → подключение носителя» |
| Высокий | обнаружен вредоносный объект; сетевая атака; заблокирован скрипт (AMSI); защита, самозащита или автозапуск выключены; попытка вмешательства в работу антивируса (самозащита заблокировала операцию); нарушена целостность антивируса; удален антивирус (MSI); служба Kaspersky отключена или аварийно завершена; 5 и более обнаружений за час |
| Средний | легальная программа, опасная в руках злоумышленника (not-a-virus: RemoteAdmin и т. п.); запуск программы запрещен (Контроль программ); доступ к устройству заблокирован (Контроль устройств); неавторизованная клавиатура (BadUSB); опасная или фишинговая ссылка; запрещенный веб-ресурс; изменены параметры или исключения; неверный пароль при операции с антивирусом; работа антивируса завершена; базы устарели или повреждены; автообновление выключено; лицензия истекла; антивирус выключен по данным Центра безопасности Windows |
| Низкий | объект обезврежен (удален, вылечен, в карантине); ошибка обновления баз; задача проверки или обновления не выполнена |

**Не считаются нарушениями (шум):** базы обновлены, задача запущена или завершена, проверка
без угроз, лицензия скоро истекает, программа запущена, сетевая активность разрешена,
запуск программы или подключение устройства разрешены, события KSN и статистика проверок.

С `-IncludeProcessCreation` (нужен аудит 4688 с командной строкой или Sysmon)
подключаются еще 5 правил запуска программ: командная строка и PowerShell, запуск из
«Загрузок»/«Рабочего стола»/Temp, браузеры, мессенджеры и игры, средства удаленного
доступа, средства администрирования (regedit, taskmgr, services.msc…).

**Свои правила:** `-SigmaRulesPath` — файлы `.yml` или папки (например, `rules\windows\builtin`
из SigmaHQ). Поддерживаются logsource product `windows` (с service, category или без них),
выборки и ключевые слова, модификаторы `contains`, `startswith`, `endswith`, `all`, `re`,
`cidr`, `exists`, `gt`/`gte`/`lt`/`lte`, `windash`, `cased`, условия `and`/`or`/`not`,
`1 of`/`all of`/`them`, корреляции Sigma v2 `event_count`, `value_count`, `temporal`,
`temporal_ordered` с `group-by`, `aliases`, `timespan`, `generate`. Необязательные поля
пакета: `evtxa_group` — группа на листах, `fields` — список `Подпись=Поле` для столбца
«Детали», `fstec239` — группы мер. Неподдерживаемые правила пропускаются, причина — на
листе «Ошибки». Правила уровня `informational` на лист «Нарушения» не выводятся.

## Меры приказа ФСТЭК России № 239

Столбцы «Меры ФСТЭК №239 (группы)» указывают **группы мер**, к которым относится сценарий:
ИАФ (идентификация и аутентификация), УПД (управление доступом), ОПС (ограничение
программной среды), ЗНИ (защита машинных носителей информации), АУД (аудит безопасности),
АВЗ (антивирусная защита), ЗИС (защита информационной (автоматизированной) системы и
её компонентов), ОДТ (обеспечение доступности). Это ориентир для аналитика — к какому
разделу требований относится находка, — а не вывод о (не)выполнении конкретной меры.

## Скорость

- Отбор на стороне Windows: XPath-запрос по провайдеру, Event ID и простым полям
  (тип входа, SID, статус, шина диска), период `-StartTime`/`-EndTime`.
- C#-ядро (оптимизированная сборка через `Add-Type`): разбор XML, правила, Sigma,
  запись находок — в 7–8 раз быстрее совместимого режима PowerShell.
- Если Windows отклонит запрос с селекторами Sigma, файл читается без них, а не
  полным медленным просмотром.

## Ограничения

Строка «Нарушений» — факт события, подходящего под правило; законность действия
(заявка, плановые работы) аудитор устанавливает сам. Отсутствие строки не доказывает
отсутствие нарушения: нужен соответствующий журнал и включенный аудит (для учетных
записей — подкатегории «Управление учетными записями пользователей» и «Управление группами
безопасности», `auditpol /get /category:"Управление учетными записями"`) (см. «Сводка» и
«Качество_выгрузки»; правило с количеством 0 могло не сработать из-за отсутствия журнала).
«Вероятный пользователь» — подсказка, а не доказательство. Цепочки строятся только внутри
одной папки и одного компьютера. В совместимом режиме PowerShell правила Sigma не применяются.

## Что проверено

SelfTest проходит в PowerShell 7.4 на Linux с параметрами по умолчанию, с `-IncludeNoise`,
`-NoCompiledEngine`, `-MaxEventId 5000 -StartTime … -EndTime …`,
`-IncludeNetworkLogons -IncludeProcessCreation -DisplayTimeZone UTC -AttackTriage`:

- C#-ядро и PowerShell-путь дают одинаковые находки байт в байт; быстрый разбор XML
  совпадает с полным XML-разбором;
- встроенный пакет Sigma загружается без пропусков;
- сквозной сценарий (подбор пароля по RDP с внешнего адреса, вход встроенным
  Администратором, скрытая УЗ и ее добавление в администраторы, флаги УЗ (без
предаутентификации Kerberos), блокировка, USB-накопитель из трех журналов,
  AnyDesk через MSI и службу, обновления Windows, очистка журнала, отключение УЗ):
  ровно 13 строк «Нарушений» с правильными уровнями, группами, пользователями, объектами УЗ
  (включая вероятного пользователя флешки и имя вместо SID) и деталями; обновления
  сигнатур пропущены; найдены цепочки «носитель → установка», «установка → очистка
  журнала», «многократные неудачные входы», «новая УЗ сразу в администраторы»;
  столбцы учетных записей на «Сводке»; листы «Правила», «Сводка», «Съемные_носители»,
  «Входы», порядок листов Excel и резервный CSV;
- Касперский: события на русском и английском из Kaspersky Event Log и параметры KES 12 в
  Application — ровно 16 строк «Нарушений» (обнаружения, «не вылечен» — критический,
  устройство, запуск программы, not-a-virus не считается ВПО, самозащита, удаление,
  служба, Центр безопасности без Defender), шумовые события (обновления, проверка без
  угроз, задачи) не попадают; цепочки «многократное обнаружение», «выключение защиты →
  носитель», «носитель → обнаружение угрозы».

**Не проверено:** Windows PowerShell 5.1 на настоящих EVTX и оформление через Excel COM —
в среде подготовки нет Windows и Excel. Сначала запустите SelfTest на своей машине.
