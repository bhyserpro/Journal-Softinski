# EVTX Audit v9.2 — офлайн-анализ выгрузок журналов Windows

Скрипт `Audit-Evtx.ps1` читает выгруженные `.evtx` (Windows PowerShell 5.1, только
встроенный .NET), отбирает значимые для ИБ события и ищет признаки компьютерных
инцидентов: цепочки атак, подбор паролей, RDP-сеансы, ослабление защиты, очистку журналов.
Результат — книга Excel (или два CSV, если Excel не установлен).
Журналы, учётные записи, политику аудита и политику исполнения скрипт не изменяет.

## Как работать с отчётом

1. **Лист «Инциденты»** (открывается первым, красная вкладка) — по строке на каждый
   кандидат в КИ. Инцидент — это все подозрительные сценарии одного компьютера, идущие
   с перерывом не больше `-IncidentGapHours` (24 ч). Строки отсортированы по оценке риска.
   В столбце «Хронология» — ход атаки по времени:
   `09:50 [P1] Password spraying → 10:01 [P1] Отказы RDP → успешный вход → 10:05 [P1] RDP-сеанс: создание УЗ → …`.
   «Цепочка атаки = Да» — на компьютере несколько значимых сценариев **разных тактик**
   (например, доступ к учётным данным + закрепление + сокрытие следов); такой инцидент
   поднимается до P1.
2. **Лист «Приоритетные»** (оранжевая вкладка) — подробности по каждому сценарию.
   Отфильтруйте столбец **КИ** по номеру инцидента и пройдите строки сверху вниз.
   P1 подсвечены красным, P2 — жёлтым. Первые три столбца (КИ, Приоритет, Оценка)
   закреплены при прокрутке.
3. По ссылкам «Находка N; файл; Record ID» переходите к исходным событиям на листе
   «Находки» (фильтр по столбцу «Номер») или в сам EVTX.
4. Контекст: «Подбор_пароля» (все серии отказов), «RDP_итоги» (суммарное время RDP
   по УЗ и IP), «RDP_сеансы» (каждый сеанс с длительностью), «Качество_выгрузки» и
   «Ошибки» — чего не хватает в выгрузке и где анализ неполный.

### Столбцы листа «Приоритетные»

| Столбец | Что в нём |

| Подбор пароля к УЗ | 55 (45 для 4771/4776 с внутреннего адреса) | серия отказов одной УЗ с одного источника |

указано, как подтвердить или закрыть строку.

## Что нового в v9.2

- Новый лист **«Инциденты»** и переработанный лист **«Приоритетные»** (см. выше): оценка
  риска, MITRE ATT&CK, отдельные столбцы УЗ и IP, сортировка по риску, местное время.
- Новые детекторы: PsExec/Impacket-службы, исключения и отключение Defender,
  угроза → отключение защиты, отключение/падение служб защиты, RDP с внешнего IP,
  временная УЗ, новая УЗ → RDP, массовые блокировки, остановка журналирования без
  перезагрузки, опасные права, SID History, группы RDP/WinRM, действия 4648 и очистка
  журнала внутри RDP-сеанса. Серии подбора пароля теперь попадают в «Приоритетные».
- Оформление Excel: порядок листов по важности, цвет P1/P2 и «Высокий/Средний»,
  тёмная шапка, перенос текста и ширина столбцов, числовые столбцы (оценка, количество,
  длительность) — числа, а не текст, технические столбцы «Находок» скрыты
  (SHA256, канал, полный путь и т.п. — раскрываются обычным «Показать»).
- Ещё меньше шума: 4723 (смена пароля самим пользователем), 4946–4948 (правила
  брандмауэра — их массово создают обновления приложений) убраны в `-IncludeNoise`;
  4672/4648 учёток компьютеров (`ИМЯ$`) и DWM/UMFD не попадают в находки.
- **Ускорение ядра** (замер PowerShell 7 на одном типовом событии 4625, 21 поле):

  | Этап | v9.1 | v9.2 |
  |---|---|---|
  | разбор события | ~640 мкс | ~210–260 мкс |
  | запись находки | ~605 мкс | ~230–250 мкс |

  Быстрый разбор читает типовой XML Windows регулярными выражениями; всё нестандартное
  (UserData, CDATA, управляющие символы, вложенные элементы…) уходит в прежний
  XML-разбор. Совпадение результатов проверяется SelfTest. Поля события извлекаются
  один раз вместо ~28 вызовов функции. На Windows PowerShell 5.1 замера нет.

## Что было в v9.0–v9.1

- XPath-фильтр на стороне Windows: Event ID > 10000 не читаются (`-MaxEventId`),
  общий отбор Critical/Error выключен (`-IncludeAllErrors`), успешные 4776 и 4672/4648
  системных УЗ отсекаются, период `-StartTime`/`-EndTime`.
- События по согласованному списку, RDP-сеансы по Security (4624/4778 → 4634/4647/4779)
  и TerminalServices-LocalSessionManager (21/25 → 23/24) с длительностью, лист «RDP_итоги».

## Параметры

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `-InputPath` / `-OutputPath` | — | папка (или файл) с EVTX / папка для отчёта |
| `-StartTime` / `-EndTime` | нет | анализировать только период (локальное время машины аналитика) — самый сильный способ ускорить |
| `-IncidentGapHours N` | 24 | сценарии одного компьютера с перерывом ≤ N ч объединяются в один КИ |
| `-DisplayTimeZone 'Id'` | пояс этого ПК | пояс для столбцов «(местное)», например `'Russian Standard Time'` |
| `-TriageWindowMinutes` | 30 | окно для цепочек (создание УЗ → права, RDP → действие и т.п.) |
| `-FailureThreshold` / `-WindowMinutes` / `-SprayUserThreshold` | 10 / 10 / 5 | пороги подбора пароля |
| `-MaxEventId N` | 10000 | события с Event ID больше N не анализируются |
| `-IncludeAllErrors` | выкл. | вернуть общий отбор любых Critical/Error |
| `-IncludeNoise` | выкл. | вернуть все убранные события и фильтры |

Параметры записываются в лист «Запуск» и `Run.json`.

## Проверка и запуск

Откройте новое окно Windows PowerShell. Скрипт не изменяет политику исполнения.
Если SelfTest завершится ошибкой, основной анализ не начнётся.

```powershell
cd "C:\Users\VATukkaev\Desktop\audit script"
$ErrorActionPreference = 'Stop'
$EvtxRunner = [scriptblock]::Create(
    (Get-Content -LiteralPath '.\Audit-Evtx.ps1' -Raw -Encoding UTF8 -ErrorAction Stop)
)
try {
    & $EvtxRunner -SelfTest

    $Logs = Read-Host 'Вставьте общую папку с логами'
    $Out = Read-Host 'Вставьте папку для новых результатов'
    $RunParams = @{
        InputPath  = $Logs.Trim().Trim('"')
        OutputPath = $Out.Trim().Trim('"')
        # StartTime = '2026-09-01'   # раскомментируйте, чтобы ограничить период
    }
    & $EvtxRunner @RunParams
} catch {
    Write-Host 'Остановлено из-за ошибки:' -ForegroundColor Red
    $_.Exception.Message
    $_.ScriptStackTrace
}
```

Успешный SelfTest заканчивается строкой `ALL SELFTESTS PASSED — version 9.2.0`.

После каждого файла печатается время, число прочитанных записей, находок и режим
отбора. Если показан **«Полный просмотр (fallback)»**, Windows отвергла
фильтрованный запрос — тогда файл читается целиком и медленно; причина сохранена
в листе «Файлы». Сообщите о таком случае: значит, запрос нужно упростить.

Расширенные режимы `-DeepScriptScan`, `-IncludeProcessCreation`, `-IncludeMessages`,
`-IncludeAllAntivirusEvents` увеличивают объём анализа — не включайте их без нужды.

## Дальнейшие способы ускорения (не реализованы)

1. **Параллельная обработка файлов (RunspacePool)** — почти пропорционально числу ядер
   на выгрузках из многих файлов. Требует переделки общего состояния и проверки на Windows.
   Уже сейчас можно запускать несколько окон PowerShell по папкам разных компьютеров.
2. **Горячий цикл на C# через `Add-Type`** — быстрее в разы, но компиляция через csc.exe
   может блокироваться AppLocker/EDR.
3. **Предварительное сокращение файлов:** `wevtutil epl Security.evtx small.evtx
   /lf:true /q:"<XPath>"`.
4. **Для очень больших объёмов** — Hayabusa или Chainsaw (Rust, без Windows API).

## Ограничения

Строки «Инцидентов» и «Приоритетных» — кандидаты на проверку, а не доказанные КИ.
Отсутствие строки не доказывает отсутствие атаки: нужны соответствующие журналы и
включённый аудит (см. «Качество_выгрузки»). Убранные из набора события в отчёт не
попадают — при расследовании конкретного инцидента используйте `-IncludeNoise`
и узкий период `-StartTime`/`-EndTime`.

Цепочки строятся только внутри одной папки и одного компьютера и не строятся через
ошибки чтения, восстановленный XML, изменение времени, загрузку ОС и очистку журнала.
«RDP-вход с внешнего IP» считает публичным всё, кроме частных, служебных и
документационных диапазонов; адрес VPN-шлюза или NAT будет внутренним.
Сохраняется предел 100000 уникальных кандидатов цепочек на запуск.

## Что проверено

SelfTest (≈ 230 проверок) проходит в PowerShell 7.4 на Linux с параметрами по умолчанию,
с `-IncludeNoise`, `-IncludeAllErrors`, с `-MaxEventId 5000 -StartTime … -EndTime …`
и с `-DisplayTimeZone UTC -IncidentGapHours 2`. Кроме тестов прошлых версий:

- быстрый разбор совпадает с полным XML-разбором на 13 образцах (включая формат
  `ToXml()` Windows, сущности, пустые и безымянные поля, Binary, UserData, CDATA,
  управляющие символы, вложенные элементы); испорченный XML по-прежнему отвергается;
- сквозной сценарий атаки (spraying с внешнего IP → подбор RDP → УЗ-бэкдор → админы →
  служба PsExec → Defender: угроза, отключение, исключение → отключение WinDefend →
  удаление УЗ → очистка журнала): обнаружены все 15 ожидаемых сценариев, один КИ P1
  с цепочкой атаки, у «чистого» компьютера нет ни одной строки;
- тот же сценарий по настоящему пути XML → разбор → правило → находка → корреляция
  отказов → приоритизация: 11 сценариев и один КИ P1;
- раскладка Excel (порядок листов, числовые/текстовые столбцы, скрытые столбцы,
  буквы столбцов) и резервный CSV-отчёт.

**Не проверено:** Windows PowerShell 5.1, чтение настоящих EVTX через Windows API и
оформление через Excel COM (цвета, ширина, скрытие столбцов) — в среде подготовки нет
Windows и Excel. Ошибки оформления не мешают созданию книги: каждое действие
обёрнуто так, что при сбое лист остаётся с данными без форматирования. Сначала
запустите SelfTest на своей машине.

История версий — в git (исходный `Audit-Evtx-Final-v8.1.ps1` в первом коммите).
