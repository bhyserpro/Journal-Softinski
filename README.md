# EVTX Audit v9.0 — офлайн-анализ выгрузок журналов Windows

Скрипт `Audit-Evtx.ps1` читает выгруженные `.evtx` (Windows PowerShell 5.1, только
встроенный .NET), отбирает значимые для ИБ события, строит RDP-интервалы, серии
отказов аутентификации и приоритетные цепочки, сохраняет отчёт в XLSX (или два CSV).
Журналы, учётные записи, политику аудита и политику исполнения скрипт не изменяет.

## Что изменено в v9 (ускорение)

Главный источник медленной работы — объём событий, которые доходят до PowerShell:
каждое отобранное событие проходит `ToXml()`, XML-разбор, правила, SHA256 и запись
в CSV. Поэтому v9 уменьшает объём **на стороне Windows API (XPath-фильтр)**, до
PowerShell.

1. **Сокращён набор Event ID: 82 правила вместо 113.** Убраны шумные и чисто
   эксплуатационные события (список ниже). `-IncludeNoise` возвращает полный набор v8.1.
2. **Event ID больше 10000 не анализируются** (`-MaxEventId`, по умолчанию 10000).
   В таблице правил таких ID не было, но общий отбор Critical/Error и журналы
   сторонних антивирусов захватывали, например, DistributedCOM 10016/10010.
   Ограничение действует и в XPath, и в правилах (включая полный просмотр-fallback).
3. **Общий отбор «любое событие уровня Critical/Error» выключен по умолчанию.**
   В System/Application это обычно самая большая и наименее полезная часть находок.
   Включается `-IncludeAllErrors` (или `-IncludeNoise`).
4. **Успешные 4776 (Status 0x0) отбрасываются фильтром Windows.** Раньше они читались
   и отбрасывались уже в PowerShell; на контроллерах домена это основной объём 4776.
5. **4672 (специальные привилегии при входе) — в шуме.** Это контекст, а не
   признак атаки; событие генерируется при каждом входе администратора и служб.
6. **Новый фильтр по периоду: `-StartTime` / `-EndTime`.** Условие добавляется в
   XPath, события вне периода Windows не отдаёт вовсе. Самый сильный рычаг, если
   нужен конкретный интервал (например, последние 2 недели перед инцидентом).
7. Мелкие правки цикла: `Handle-Rdp` и `Save-Failure` вызываются только для
   событий, которые на них влияют; `BatchSize` чтения 256 → 1024; в приоритизации
   проекция строк без `Select-Object` на каждую строку.

Что сознательно **не** менялось: окна корреляции, пороги, логика цепочек, формат
отчётов, разбор XML и SHA256 каждого события.

## Новые параметры

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `-MaxEventId N` | 10000 | события с Event ID больше N не анализируются |
| `-IncludeAllErrors` | выкл. | вернуть общий отбор любых Critical/Error |
| `-IncludeNoise` | выкл. | вернуть полный набор v8.1 (все убранные ID + Critical/Error) |
| `-StartTime` / `-EndTime` | нет | анализировать только период; время — локальное время машины аналитика, переводится в UTC |

Параметры v9 записываются в лист «Запуск» и `Run.json`.

## Проверка и запуск

Откройте новое окно Windows PowerShell. Скрипт не изменяет политику исполнения.
Если SelfTest завершится ошибкой, основной анализ не начнётся.

```powershell
cd "C:\Users\VATukkaev\Desktop\audit script"
$ErrorActionPreference = 'Stop'
$EvtxRunner = [scriptblock]::Create(
    (Get-Content -LiteralPath '.\Audit-Evtx.ps1' -Raw -Encoding UTF8 -ErrorAction Stop)
)
try {
    & $EvtxRunner -SelfTest

    $Logs = Read-Host 'Вставьте общую папку с логами'
    $Out = Read-Host 'Вставьте папку для новых результатов'
    $RunParams = @{
        InputPath  = $Logs.Trim().Trim('"')
        OutputPath = $Out.Trim().Trim('"')
        # StartTime = '2026-09-01'   # раскомментируйте, чтобы ограничить период
    }
    & $EvtxRunner @RunParams
} catch {
    Write-Host 'Остановлено из-за ошибки:' -ForegroundColor Red
    $_.Exception.Message
    $_.ScriptStackTrace
}
```

Успешный SelfTest заканчивается строкой `ALL SELFTESTS PASSED — version 9.0.0`.

После каждого файла печатается время, число прочитанных записей, находок и режим
отбора. Если показан **«Полный просмотр (fallback)»**, Windows отвергла
фильтрованный запрос — тогда файл читается целиком и медленно; причина сохранена
в листе «Файлы». Сообщите о таком случае: значит, запрос нужно упростить.

Расширенные режимы `-DeepScriptScan`, `-IncludeProcessCreation`, `-IncludeMessages`,
`-IncludeAllAntivirusEvents` увеличивают объём анализа — не включайте их без нужды.

## Дальнейшие способы ускорения (не реализованы в v9)

По убыванию ожидаемого эффекта:

1. **Параллельная обработка файлов (RunspacePool).** Каждый EVTX обрабатывается
   независимо, поэтому на 4–8 ядрах выгрузка из многих файлов может ускориться
   почти пропорционально числу ядер. Требует переделки общего состояния (номера
   находок, writers, сводка) — каждый поток пишет свои временные CSV, затем
   слияние с перенумерацией. Существенная переработка; делать отдельно, с проверкой
   на Windows.
2. **Горячий цикл на C# через `Add-Type`.** Разбор XML, правила и запись CSV на C#
   быстрее PowerShell в десятки раз. Минус: `Add-Type` компилирует код через csc.exe,
   что может блокироваться AppLocker/EDR, и логику придётся поддерживать в двух местах.
3. **Предварительное сокращение файлов:** `wevtutil epl Security.evtx small.evtx
   /lf:true /q:"<XPath>"` — сохранить в новый EVTX только нужные события (можно
   выполнять на машине-источнике, чтобы передавать меньшие выгрузки).
4. **Запуск по частям:** отдельный запуск по папке каждого компьютера уменьшает
   память корреляции и позволяет запускать несколько окон PowerShell параллельно
   (это уже работает без изменений скрипта).
5. **Для очень больших объёмов** — специализированные инструменты (Hayabusa,
   Chainsaw), они написаны на Rust и разбирают EVTX без Windows API.

Что пробовалось и **не** оставлено: замена XPath-разбора события на ручной обход
узлов и замена JSON во временных файлах корреляции на TSV. На PowerShell 7 замер
не показал выигрыша (на Windows PowerShell 5.1 замера нет), поэтому эти места
оставлены как в v8.1 ради меньшего риска.

## Результат и ограничения

При установленном Excel создаётся XLSX с листами «Приоритетные», «Находки»,
«Подбор_пароля», «RDP_сеансы», «Файлы», «Качество_выгрузки», «Ошибки», «Запуск».
Без Excel сохраняются два CSV с UTF-8 BOM и разделителем `;`.

Приоритетные строки — кандидаты на проверку, а не доказанные инциденты. Отсутствие
строки не доказывает отсутствие атаки: нужны соответствующие журналы и включённый
аудит. **Сокращение набора Event ID в v9 означает, что убранные события не попадут
в отчёт** — при расследовании конкретного инцидента используйте `-IncludeNoise`
и/или узкий период `-StartTime`/`-EndTime`.

Сохраняется предел 100000 уникальных кандидатов цепочек на запуск. При достижении
лимита затронутые области помечаются как неполные — запускайте такие выгрузки
отдельно по компьютерам.

## Что проверено

- SelfTest (все тесты v4–v8.1 + новые v9) проходит в PowerShell 7.4 на Linux
  с параметрами по умолчанию, с `-IncludeNoise` и с
  `-IncludeAllErrors -MaxEventId 5000 -StartTime … -EndTime …`.
- Новые тесты v9: нет правил выше MaxEventId; событие 10016 уровня Error не даёт
  находку (и в журнале антивируса); общий Critical/Error следует `-IncludeAllErrors`;
  шумные ID исключены, ключевые оставлены; XPath-запрос — корректный XML, каждый
  селектор ограничен явными ID или MaxEventId, 4776 выбирается только с Status != 0x0.
- **Не проверено:** Windows PowerShell 5.1 и чтение настоящих EVTX через Windows API
  (в среде подготовки нет Windows). Фактическое ускорение на ваших данных не измерено —
  оно зависит от доли убранных событий. Сначала запустите SelfTest на своей машине
  и сравните время по листу «Файлы» с прошлым запуском v8.1.
