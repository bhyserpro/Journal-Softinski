# EVTX Audit v8.1 — исправление передачи событий в корреляцию

## Оптимизация v8.1

Это версия v8 с оптимизацией вычислений. Новых исключений Event ID, сокращения
временных окон, выборки «каждого десятого» события и отключения корреляций нет.

- Запись CSV: преобразование 46 ячеек находки выполняется внутри одной функции,
  без отдельного вызова Cell на каждую ячейку. Экранирование формул, кавычек,
  переводов строк, недопустимых символов и прежние ограничения длины сохранены.
- Отказы аутентификации: число разных пользователей в скользящем окне обновляется
  при добавлении/удалении события. Повторный обход всего окна после каждого отказа
  исключён. Для этой части вычислений сложность одного обновления стала в среднем
  постоянной вместо линейной по размеру окна. Это не оценка ускорения всего запуска.
- Приоритизация читает строки CSV потоком, не материализуя весь файл находок.
  Существующий предел кандидатов и все правила полноты сохранены.
- SHA256 переиспользует экземпляр алгоритма; хеш содержимого каждого события
  по-прежнему вычисляется. Хеш имени раздела временных файлов вычисляется один раз
  на раздел, вместо повторного вычисления для каждого отказа.
- Объекты настроек XML и неизменяемые запросы отбора переиспользуются.
  XML-разбор, запрет DTD и обработка недопустимых символов сохранены.
- После каждого EVTX показываются секунды, число прочитанных записей, находок и
  режим отбора. Отдельно показывается время корреляции и упаковки Excel/CSV.

Фактическое ускорение зависит от количества событий, накопителя, Windows API и
Excel. Замера на ваших файлах нет; обещания «20 минут превратятся в 2» здесь нет.
Если показан «Полный просмотр (fallback)», Windows отвергла фильтрованный запрос;
причина сохранена в листе «Файлы». Полный просмотр оставлен ради полноты проверки.

Статически сверены с v8: таблица правил, Match-Event, Parse-Event, Add-Triage,
Add-SingleTriage, обе функции цепочек, связь отказов с успешным RDP, обработка RDP
и Test-V8 — без изменений. Проверены все 21 именованный вызов Add-Triage.

В SelfTest дополнительно включены сравнения с реализацией v8:
точное совпадение CSV-экранирования, SHA256 и всего CSV групп отказов на 1200
синтетических событиях с дубликатами, истечением окна и очисткой очередей.
Эти исполняемые проверки здесь не запускались из-за ограничения .NET, указанного
ниже. Нужен успешный SelfTest на Windows. Он не читает ваши журналы.

## Что было сломано

В версии 7.1.3 функция Add-Triage ожидала 8 аргументов: Groups, Priority, Scenario,
Evidence, Why, Check, Object, Rows. В 19 из 21 вызова передавалось только 7.
Не хватало Why: текст проверки попадал в Why, объект — в Check, массив событий —
в Object, а Rows оставался пустым. Поэтому создание приоритетной находки не
происходило. Два полных вызова, включая прямой тест CSV-строки, могли проходить.
Это объясняет, почему последовательное удаление падающих тестов не помогало.
Предыдущие объяснения про несовместимость скобок/коллекций PowerShell не были
подтверждены и не описывали основную причину.

Теперь все 21 вызов используют именованные параметры; пропустить Rows или
сдвинуть аргументы незаметно нельзя. Функция проверяет поля доказательств и
запрещает смешивать компьютеры и папки. Удалённые проверки службы и задания
восстановлены. WMI-корреляция остаётся отключённой по ранее согласованному решению;
исходные Sysmon 19/20/21 остаются в базовых находках.

## Другие исправления

- Дубли удаляются перед подсчётом порога отказов и построением цепочек.
- При 4625 SID может быть S-1-0-0, а при 4624 — настоящим SID. Для таких случаев
  используется точное полное имя DOMAIN\user (или UPN) и IP. Если оба SID известны,
  они дополнительно обязаны совпасть. Неоднозначные короткие имена без SID не связываются.
- Связка отказов требует 4625 типа 10, кода неверного пароля, затем успешного 4624
  типа 10. NLA-отказы типа 3 в этой цепочке не учитываются: они не доказывают RDP.
  Они по-прежнему могут входить в общую группировку отказов.
- Данные дополнительно разделяются по папке выгрузки и имени компьютера внутри
  самой функции корреляции; совпадение имени УЗ между компьютерами недостаточно.
- Logon ID нормализуется: 0x000abc и 0xabc считаются одинаковыми.
- После 4634 действия больше не связываются с завершённым RDP-сеансом.
- Для загрузки, изменения времени и очистки учитываются и провайдер, и Event ID.
- Временная сортировка выполняется по числовому времени UTC один раз на область,
  вместо двух сортировок. Числовой Record ID служит дополнительным порядком.
- Предупреждение о порядке времени в Application.evtx не блокирует цепочки
  Security.evtx, если Application не был источником кандидатов этой цепочки.
- Реальные ошибки чтения/разбора, изменение входного файла и нарушение хронологии
  в источнике кандидатов по-прежнему ограничивают корреляцию. Это намеренное
  ограничение полноты, а не подтверждение отсутствия инцидента.

не удалены. Имя провайдера обязательно учитывается вместе с Event ID.

## Проверка и запуск

Распакуйте архив в `C:\Users\VATukkaev\Desktop\audit script`.
Откройте новое окно Windows PowerShell. Используется прежний согласованный способ
загрузки; скрипт не изменяет политику исполнения и настройки Windows.

Вставьте весь блок. Если SelfTest завершится ошибкой, основной анализ не начнётся.

```powershell
cd "C:\Users\VATukkaev\Desktop\audit script"
$ErrorActionPreference = 'Stop'
$EvtxRunner = [scriptblock]::Create(
    (Get-Content -LiteralPath '.\Audit-Evtx-Final-v8.1.ps1' -Raw -Encoding UTF8 -ErrorAction Stop)
)
try {
    & $EvtxRunner -SelfTest

    $Logs = Read-Host 'Вставьте общую папку с логами'
    $Out = Read-Host 'Вставьте папку для новых результатов'
    $RunParams = @{
        InputPath  = $Logs.Trim().Trim('"')
        OutputPath = $Out.Trim().Trim('"')
    }
    & $EvtxRunner @RunParams
} catch {
    Write-Host 'Остановлено из-за ошибки:' -ForegroundColor Red
    $_.Exception.Message
    $_.ScriptStackTrace
}
```

Полное прохождение тестов заканчивается только строкой:

`ALL SELFTESTS PASSED — version 8.1.0`

Для проверки без чтения EVTX достаточно `& $EvtxRunner -SelfTest`.
SelfTest использует фиксированные тестовые пороги; производственные параметры
основного запуска остаются заданными вами.

Не добавляйте в первый запуск DeepScriptScan, IncludeProcessCreation,
IncludeMessages или IncludeAllAntivirusEvents. Эти расширенные режимы увеличивают
объём анализа. Формирование Windows-описаний по умолчанию отключено; русское
описание правила и XML-поля остаются. Excel AutoFit на больших листах отключён.
Время по каждому файлу указано в листе «Файлы».

## Результат и ограничения

При установленном Excel создаётся XLSX с листами, включая «Приоритетные», базовые
находки, подбор пароля, RDP, файлы и ошибки. Если Excel недоступен, сохраняются
два CSV с UTF-8 BOM и разделителем `;`. Event ID находится слева в «Приоритетных».

Приоритетные строки — кандидаты на проверку, не доказанные инциденты. В них есть
описание связи, время UTC, компьютер, объект, Event ID и ссылки на файл/Record ID.
Отсутствие строки не доказывает отсутствие атаки: необходимы соответствующие
журналы и включённый аудит. Удалённый доступ не ограничивается RDP, а скрипт не
вычисляет длительность всех возможных протоколов удалённого управления.

Сохраняется предел 100000 уникальных кандидатов цепочек на запуск для ограничения
памяти. При достижении лимита затронутые области помечаются как неполные; запускайте
такие выгрузки отдельно по компьютерам. Лимит не означает пропуск базовых находок.
